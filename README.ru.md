Задача практическая: вставили зарядку — планшет заряжается; заменили её на SSD или устройство OTG — работает USB; вернули зарядку — питание определяется без перезагрузки Windows. **Сборка 1868 показывает хорошие результаты в проверенных последовательностях**, включая прямой USB-C накопитель, флешку через OTG, повербанк и хаб с питанием.

В архиве — **точные файлы драйверов, которые сейчас работают на планшете проекта**, установщик с запуском двойным нажатием, проверенная резервная копия и скрипт диагностики. Это предварительная сборка сообщества для **Xiaomi Pad 5 / nabu**, а не официальный или универсально стабильный релиз.

> **Оставшийся баг:** при снятии зарядки с Acer HY41-T9 SSD кратко отключается и появляется снова. Возврат зарядки восстанавливает питание. Непрерывная работа USB при таком переключении питания **ещё не исправлена**.

**Требования:** Xiaomi Pad 5 (nabu), Windows 11 ARM64, установленные базовые драйверы nabu и **уже активный Test Mode**. Пакет проверяет совместимую версию и хеш battery miniclass; полный набор базовых драйверов он не заменяет. Если система ещё не подготовлена, используйте [инструкцию проекта nabu по загрузке и подписи](https://github.com/erdilS/Port-Windows-11-Xiaomi-Pad-5/blob/main/guide/English/disable-secureboot-en.md).

1. Скачайте и **полностью распакуйте ZIP** в папку на внутреннем диске Windows планшета.
2. Дважды нажмите **`Install.cmd`** и разрешите запрос администратора. Используется штатный Windows PowerShell; Python, SDK и ручной выбор INF не нужны.
3. Дождитесь **«Driver set staged; reboot manually»**. Сохраните работу, безопасно извлеките USB-накопители и перезагрузитесь вручную.
4. После перезагрузки запустите **`Diagnose.cmd`**. У пяти строк должны совпадать версии и хеши, `Running=True`, `ProblemCode=0`.

Если Install сообщил об ошибке, сохраните протокол и запустите диагностику; не считайте такую установку успешной. Повторный запуск на совпадающем наборе ничего не меняет. Установщик отклоняет другие модели, неполный архив, несовместимый базовый miniclass и автоматическое понижение версии драйверов.

Перед подготовкой четырёх обновляемых пакетов Install сохраняет **все пять прежних пакетов INF/SYS/CAT** на внутренний диск и проверяет хеши. Windows активирует новый набор после ручной перезагрузки. При необходимости установщик добавляет только **открытый** сертификат разработки в Root/TrustedPublisher. BCD/Secure Boot и драйверы камеры не меняются; автоматической перезагрузки нет.

Предварительная проверка без установки и изменения сертификатов:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -CheckOnly
```

## Зарядка настоящая? А быстрая зарядка?

Для проверки используются **события согласования USB PD и документированная телеметрия драйвера батареи**, а не одна иконка. В последних тестах 1868 батарея уже была на 100%: питание определялось, значения мощности батареи были положительными, но ёмкость оставалась ограничена полным зарядом. Это поддерживает вывод о зарядке/подзарядке, но не доказывает новый прирост ёмкости или максимальную скорость.

Ранее завершённые **8-минутные тесты сборки 1867** показали прирост энергии по данным батареи:

| Источник | Прирост энергии по телеметрии | Средняя мощность батареи |
|---|---:|---:|
| Повербанк | 0,911 Вт·ч | 8,04 Вт |
| Блок для iPhone | 0,945 Вт·ч | 8,43 Вт |
| Блок Samsung | 0,911 Вт·ч | 8,19 Вт |

Это показания драйвера батареи, **не внешнего измерителя на входе USB**, и не тест максимальной скорости сборки 1868.

В записях 1868 повербанк согласовал **9 В × 2 А**, блоки для iPhone и Samsung — **12 В × 1,5 А**. Это **лимит контракта/запроса 18 Вт**, а не утверждение, что батарея получает 18 Вт. Влияют нагрузка планшета, уровень заряда, температурная политика, кабель и хаб.

Проверенные блок Samsung и повербанк объявляли поддержку PPS, но **Windows не запрашивала PPS**. Обычная индикация зарядки Windows не доказывает скорость; надпись «быстрая зарядка» в Android тоже не подтверждает контракт или мощность в Windows. Максимальная быстрая зарядка на уровне Android в этом релизе не обещана.

## Известный баг хаба

На **Acer HY41-T9 + Kingston XS2000** снятие только кабеля PD-зарядки приводит к краткому исчезновению и повторному появлению SSD. Возврат кабеля восстанавливает зарядку; в последних пользовательских циклах повторного обрыва SSD при возврате не наблюдалось.

Следующая цель — сохранить USB-сессию при смене питания хаба. Обрыв воспроизводится, но точный вклад переключения питания самого хаба и последовательности USB-C/ролей Windows ещё нужно доказать. **Пока не установлено, что проблему этого хаба можно полностью убрать только драйвером.** В 1868 не добавлен подтверждённый механизм FRS/бесшовного переключения.

Не меняйте питание хаба во время записи на диск; при необходимости используйте безопасное извлечение. Даже короткое исчезновение тома может прервать работу приложения. Пользователь также сообщал о возможном переподключении при первой вставке хаба, но точная последовательность событий ещё не установлена.

## Что входит в сборку 1868?

Номер набора — **1868**; версии компонентов отличаются:

| Компонент | Версия INF | Действие установщика |
|---|---|---|
| `qcpmicext` | 1.0.1866.0 | Установить |
| `qcpmictcc` | 1.0.1867.0 | Установить |
| `qcusbctcpm` | 1.0.1853.0 | Установить |
| `qcbattmngr` | 1.0.10732.0 | Установить |
| `qcbattminiclass` | 1.0.1680.0 | Оставить установленный; точные файлы в `reference/` |

Неизменённый miniclass сохраняет исходную подпись сообщества, не переподписывается и не устанавливается. Его точный хеш SYS требуется как проверенная база. Четыре изменённых пакета имеют подпись разработки/тестовую подпись, а не производственную WHQL. Историческое имя открытого сертификата содержит `NabuCameraDev`; его использование не устанавливает и не меняет драйверы камеры.

По сравнению с 1867, **1868 меняет обработку обновления напряжения/мощности в менеджере батареи, когда лимит тока не меняется**. Ранее такое обновление могло игнорироваться. Узкое исправление сохраняет специальные случаи и не добавляет записи в регистры PMIC, новые команды протокола, таймеры или потоки. Офлайн-проверки прошли **1 728 исполнений ARM64 callback и 563 проверки native unwind**, без ошибок. Конкретный переход напряжения при неизменном токе ещё требует аппаратного подтверждения; это не исправление обрыва хаба.

Пакет также прошёл предварительную проверку Windows PowerShell 5.1, реальное создание диагностического отчёта, восемь проверок принадлежности SYS/INF подписанным каталогам и двенадцать проверок архива, копирования и защит установщика. Во время этих проверок драйверы рабочего планшета **не переустанавливались**. [Хеши и подробности проверки](docs/BUILD1868.md).

## Диагностика и возврат

**`Diagnose.cmd`** создаёт локальный ZIP в `%LOCALAPPDATA%\SK-Charging-Diagnostics`: версии, хеши и состояние драйверов, проблемы PnP, USB/накопители, недавние относящиеся к проблеме события System и стандартная телеметрия батареи. Скрипт не устанавливает и не сбрасывает устройства, не использует частные управляющие PMIC IOCTL и не отправляет данные в сеть.

Для пяти минут замеров батареи:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Diagnose.ps1 -Seconds 300
```

Перед публикацией просмотрите диагностический ZIP: USB ID и сообщения событий могут содержать серийные номера и локальные пути. В [сообщении о проблеме](https://github.com/deskcj/xiaomi-pad5-windows11-charging/issues) укажите номер сборки, сборку Windows, модели хаба/зарядника/устройства и последовательность подключения. Делитесь проверенными вами диагностическими данными; сырые дампы памяти не требуются.

Протоколы и проверенные копии находятся в `%ProgramData%\SK-Charging\Install-*`. Для возврата к конкретному сохранённому набору безопасно извлеките и отключите USB-накопители, затем запустите **`Restore.cmd` внутри его папки `Previous`**. Restore из основного архива выбирает последнюю копию. Возврат может перезапустить USB/зарядку; после него перезагрузитесь вручную. Сохраните указанный путь копии и обычный способ восстановления Windows на случай отказа загрузки. [Полная инструкция](tools/community1868/README.ru.md).
