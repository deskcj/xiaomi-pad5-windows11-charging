# Nabu PMIC fix20r1 — экспериментальный кандидат

**Собран, но не установлен и не проверен загрузкой Windows.** Это ремонт конкретных дефектов fix20, а не новый полноценный Android-подобный стек питания. Код определения роли по 0x1509 и изменения VCONN из fix20 сохранены; их правильность с реальным хабом не доказана.

Для Xiaomi Pad 5 nabu / Windows 11 ARM64, фактическая база исследования — build 26100. Аппаратный ID `ACPI\QCOM05E5`, батарейный miniclass должен оставаться **1680**. Другие модели/версии Windows не проверены.

## Изменения и проверки

- Восстановлены четыре константы измерений и ранее занятые кодом участки исходного драйвера.
- Ошибочный trampoline заменён функцией `src/role_repair.c`, собранной MSVC ARM64. Проверяется готовность PMIC-контекста для всех ролей и результат каждой дополнительной операции чтения/записи.
- Параметры, стек и изменяемые/сохраняемые регистры обрабатываются по ABI; исходный индекс не подменяется нулём.
- Новый код — отдельная RX-секция, unwind-метаданные — отдельная R-секция. Новых импортов и RWX-секций нет; исходная таблица исключений сохранена и дополнена пятью записями компилятора.
- **1 624** сценарий выполнения реальных ARM64-инструкций в Unicorn; все 256 значений состояния порта, ошибки транспорта и разные результаты вызовов.
- **93** контекста на границах инструкций проверены настоящей Windows ARM64 `RtlVirtualUnwind`, включая частично исполненные прологи/эпилоги. Приложение отображало SYS как неисполняемые данные и не загружало его в ядро.
- Подписанная сборка побайтно совпала по секциям с проверенной неподписанной. Проверены PE checksum, подпись каталога и принадлежность SYS каталогу.

Проценты батареи, реальная мощность, USB-хаб, прямой кабель, накопитель, сон и загрузка после перезапуска **ещё не проверены с этим кандидатом**. Тестовая подпись не является Microsoft production signature; проверка `/kp` на production-доверие ожидаемо не проходит. Режим обычной Secure Boot-загрузки этот пакет не поддерживает.

## Файлы

`package/` — SYS/INF/CAT. `package-manifest.json` — версия и точные SHA-256. `NabuCameraDev-public.cer` содержит только публичный сертификат, без закрытого ключа.

`Install-PmicPackage.ps1` и `install.cmd` по умолчанию работают только на чтение. Они не удаляют PMIC-устройство, не переключают host mode, не импортируют сертификаты, не меняют BCD и не перезагружают планшет.

## Порядок будущего испытания

Сейчас разрешён только Inspect:

```powershell
.\Install-PmicPackage.ps1 -Mode Inspect
```

После подготовки recovery и отдельного решения владельца о начале испытания, из **повышенного нативного ARM64 PowerShell**:

```powershell
# Сохраняет текущий пакет, полный SYSTEM и BCD на внутреннем диске.
# Добавляет пакет в DriverStore, но не активирует его на устройстве.
.\Install-PmicPackage.ps1 -Mode Stage -AcknowledgeExperimental

# Отдельное действие. Может изменить живую PnP-привязку и прервать USB.
# Перед этим закрыть приложения/записи на внешнем диске и подготовить recovery.
.\Install-PmicPackage.ps1 -Mode Activate -AcknowledgeExperimental -StagedRecoveryDirectory 'C:\ProgramData\NabuCharging\Rollback\<каталог успешного Stage>' -ExternalRecoveryRoot 'H:\Vlad\Charging\Charging-Rollback-2026-10-26\experiments'
```

Не запускать Activate сейчас. Stage и Activate в данном этапе **не выполнялись**. Включённое тестовое подписание, отключённый Secure Boot и доверенный сертификат проверяются установщиком; сам он их не включает. Activate требует внешний накопитель и **до изменения живой привязки** сохраняет и сверяет на нём полный свежий rescue-набор. Если накопитель недоступен или копии не совпали, активация отменяется. Для восстановления использовать именно этот внешний Activate-снимок: только внутренней копии недостаточно при не загружающейся Windows.

Автоматической перезагрузки нет. После контролируемой перезагрузки сначала проверяется загрузка и базовое питание, затем матрица подключений. Не удалять Qualcomm PMIC Extension вручную и не заменять miniclass 1680 на 2100.

## Офлайн-откат именно нового эксперимента

Исходный комплект владельца `Charging-Rollback-2026-10-26` сохранён отдельно. Новый установщик создаёт дополнительную точную запись `recovery-record.json`, полный SYSTEM/BCD и копии файлов. Для нового пакета с изменённой PnP-привязкой нужен этот дополнительный набор, а не только старый файловый откат.

На ноутбуке/в recovery, когда раздел планшета смонтирован и Windows планшета не работает:

```powershell
.\Restore-ExperimentOffline.ps1 -WindowsRoot 'W:\Windows' -RecoveryDirectory 'H:\<копия последнего каталога отката>'
```

По умолчанию — просмотр. Режим `-Apply` требует повышенных прав, проверяет точный экспериментальный oem*.inf, удаляет только его через офлайн DISM, возвращает пакет базы и полный SYSTEM. Он сохраняет изменяемые файлы в отдельный rescue-undo и не переписывает BCD. **Восстановление полного SYSTEM откатит и прочие настройки системы после снимка.** Реальный Apply/аварийное восстановление в этом этапе не тестировались.

До начала эксперимента проверить возможность доступа к Windows-разделу с ноутбука. Гарантии отсутствия BSOD и восстановления любого отказа нет.
