# Что доказано и что осталось проверить

## Исходные материалы

Инвентаризированы 666 файлов исходного проекта, включая заметки, старые кандидаты и измерения. Проверены 47 выбранных файлов официального Android-ядра Xiaomi. Из сохранённого ядра и kallsyms подготовлена отдельная аналитическая ELF-копия, без изменения байтов загружаемых секций. В Ghidra сопоставлены управление OTG, Type-C power role, PD active и USB plugin.

Версия открытого дерева Xiaomi относится к 2021 году, прошивка измерений — к 2024. Полное тождество исходников прошивке не предполагается. Адреса и выводы привязаны к конкретным проверенным бинарникам.

## Входные хеши патчера

- Stock BSP SYS: `533c3a555e111d4b12b657d026c92d63d5170d57297432d03bdaf3be96c7886a`.
- Оригинальный fix20 SYS: `9955517922e3a0d13287034616c08f8dbad1322c248954477a144073f5f606d2`.
- Публичный stock INF использует другой аппаратный ID; не заменять им INF nabu QCOM05E5 только из-за совпадения SYS.

Патчер отвергает другие входы. Он не является универсальным исправлением Qualcomm PMIC для других устройств.

## Реализованные исправления

1. Четыре LDR снова получают исходные константы, потому что код из literal-пулов убран.
2. Восстановлен участок исходного кода, который fix20 занимал своей обвязкой.
3. Новый обработчик проверяет инициализацию контекста для всех ролей, не выполняет обход инициализации сырыми PMIC-записями.
4. Дополнительный путь для первого индекса выполняется только при исходном role=0. Индекс/роль других вызовов не подменяются.
5. Ошибка чтения возвращается без последующих записей; ошибка OTG-записи не маскируется успешным продолжением.
6. Компилятор создаёт unwind-метаданные для всех фрагментов обработчика. Они добавлены к полной исходной exception table. Тест Windows проверяет частично исполненные прологи и эпилоги.

Восстановление тока/напряжения не означает исправления процента батареи, физического заряда, QC/PPS или работы накопителей.

## Ограничения

Алгоритм классификации 0x1509 оставлен от fix20, а не объявлен правильным Android-алгоритмом. В Android отдельно читаются CC/роль/состояние питания, обрабатываются события, блокировки и ошибки. Один принудительный host mode не заменяет эту логику: data-host может одновременно быть power-sink.

Пять исходных CSV содержат 3/62/31 точку питания и 83/66 точек разряда. Прямая зарядка и хаб используют разные протоколы, прогоны имеют разные SOC/длительность. Предельное/договорное напряжение нельзя выдавать за измеренное VBUS. Выключенный LN8000 может отдавать остаточные значения. Утверждать аппаратный потолок хаба только по этим данным нельзя.

Повторяющиеся disk 11 относятся к пути USB SSD; они не доказывают, что виноват исключительно PMIC. Требуется сравнение хаба без SSD и с ним. События Kernel-Power 41 не равны доказанному BSOD; конкретные bugcheck и дампы рассматриваются отдельно.

## Установка из рассказа владельца

Авторский скрипт установки не сработал. Пользователь предварительно включал host mode, удалял Qualcomm Power Management PMIC Extension Device и ставил qcpmicext вручную из архива. Это сохранено как наблюдение о порядке действий, а не как рекомендуемый способ установки. Для нового пакета ручное удаление узла не используется.

## HDMI

DTS nabu ограничивает внешний usb0 режимом high-speed и отключает usb_qmp_dp_phy. Наличие HDMI на хабе не доказывает физическую поддержку DP Alt Mode планшетом. Включение HDMI не входит в исправления fix20r1. USB-видеоадаптер с подходящим ARM64-драйвером — отдельная аппаратная возможность, здесь не испытанная.
