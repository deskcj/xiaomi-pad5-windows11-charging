# Требования к зарядке и USB Xiaomi Pad 5 / nabu

Дата: 27.10.2026. Это чек-лист приёмки будущего исправления, а не инструкция
начать испытания. Сейчас разрешён только статический разбор. Установки,
перезагрузки, новые тесты и аппаратные обращения не выполнялись.

**Готового подтверждённого исправления пока нет. Ни один пункт ниже не
отмечен как пройденный новой сборкой.** Старые разовые успехи не доказывают
стабильность: после них были отказы зарядки и ошибки определения SSD.

## Какое поведение требуется

Планшет сам определяет допустимые роли питания и данных. Для подключённого
накопителя он является USB-хостом; одновременно он может получать питание
от хаба. При работе хаба без внешнего блока планшет должен питать его,
если хаб поддерживает это и хватает разрешённой мощности. Роль USB-хоста
сама по себе не означает, что планшет обязан выдавать питание во всех режимах.

«Сразу работает» означает автоматическое обнаружение и завершение штатного
согласования без ручного HostMode, удаления устройств, перезагрузки или
обязательного порядка подключения. Это не нулевая задержка протокола.
Допустимые сроки берутся из применимого протокола и измеряются позднее;
произвольный тайм-аут здесь не придуман.

## Матрица функций

Все строки пока **не подтверждены для исправленного комплекта драйверов**.
Графа «что известно» относится к старым журналам и сообщениям владельца,
а не к новым проверкам. Большинство захватов питания относятся к R5/1847;
их нельзя выдавать за измерения исходного PMIC1840.

|---|---|---|---|
| B01 | Холодный запуск без аксессуаров | Порт готов к последующему подключению любого поддерживаемого устройства | Статический пробел порядка готовности; см. BOOT-01 |
| B02 | Запуск с уже вставленной прямой зарядкой | Питание определяется автоматически, процент корректен | Полный запуск с подключённым блоком не принят |
| B03 | Запуск с хабом, зарядкой и SSD | После загрузки доступны зарядка и SSD; переставлять хаб не требуется | Исторически зависело от порядка подключения |
| B04 | Запуск с хабом и SSD без зарядки | Хаб и SSD работают от планшета при достаточном бюджете питания | Возможности конкретного хаба и переход Source не подтверждены |
| B05 | Запуск с прямой флешкой / SSD | USB-хост и питание устройства поднимаются без повторного втыкания | Для USB-C SSD наблюдались ошибки дескриптора |
| B06 | Перезагрузка с аксессуарами | Нет BSOD и зависания; подключённые устройства восстанавливаются автоматически | Нет принятой новой сборки; один успешный старт недостаточен |
| C01 | Вставить прямую зарядку в работающий планшет | Фактический приём питания, правильный статус, автоматическое согласование | Раньше были как успехи, так и отказы |
| C02 | Вставить хаб с зарядкой и SSD | SSD доступен одновременно с приёмом питания | Есть прежние разовые успехи, стабильность не доказана |
| C03 | Подключить хаб и SSD без зарядки | Планшет выдаёт допустимое питание и видит накопитель | Зафиксирована потеря накопителя без внешнего блока |
| C04 | Вставить прямой накопитель после зарядки | Приём питания прекращается, планшет становится источником для USB и видит устройство | Исторически встречались OTG-off и Code43 |
| C05 | Вынуть хаб и подключить прямую зарядку | Зарядка начинается без перезапуска стека/Windows | Бывало, что зарядка не возвращалась |
| C06 | После прямой зарядки вернуть хаб с зарядкой и SSD | Оба устройства работают; предыдущая прямая зарядка не является обязательной подготовкой | Исторически прямая зарядка иногда помогала хабу |
| C07 | После прямого накопителя вернуть весь комплект в хаб | Согласованные роли и работа обоих устройств без перезагрузки | Полная последовательность не принята |
| C08 | Обычная USB-A флешка и USB-C SSD | Каждый поддерживаемый накопитель корректно определяется на своём порту/кабеле | USB-A работала, USB-C SSD с тем же кабелем определялся на ноутбуке; причины отличаются |
| C09 | Подключение USB-C обеими ориентациями | Обе ориентации исправного кабеля одинаково работоспособны | Полная проверка отсутствует; VCONN и ориентация учитываются отдельно |
| C10 | Удалить только накопитель из питаемого хаба | Зарядка продолжает работать, хаб остаётся доступным | Полная приёмка отсутствует |
| P01 | Удалить только зарядку из хаба | Если питание хаба не обрывается, накопитель остаётся тем же работающим устройством | **Отдельная аппаратно зависимая цель**; владелец сообщил о потере SSD и в Android |
| P02 | Снятие зарядки всё же перезапустило хаб | После восстановления питания устройства снова определяются автоматически без перезагрузки Windows | Это восстановление после обрыва, а не выполнение P01 |
| P03 | Вернуть зарядку в работающий от планшета хаб | Планшет принимает питание, данные продолжают работать при поддерживаемом непрерывном переходе | Были возвраты зарядки, но также застревание без неё |
| P04 | Краткое пропадание внешнего питания / дребезг | Нет зависшего Source/Sink; восстановление следует реальному электрическому состоянию | Старый таймер Source не должен включать OTG после смены роли |
| P05 | Цепочка всех перечисленных перестановок | Каждый следующий режим работает независимо от предыдущих; нет накопления ошибочного состояния | Исторически последовательности приводили к отказу |
| D01 | Копирование при снятии только зарядки | При непрерывном питании нет USB-reset, переопределения диска, ошибок I/O; содержимое сохранено | **P01 не подтверждён. Испытания записи сейчас запрещены** |
| D02 | Хаб физически отключён целиком | Отсоединение распознано; новый аксессуар работает; активная запись не объявляется сохранённой задним числом | Продолжить I/O через вынутый кабель невозможно |
| S01 | Сон и пробуждение с любым комплектом | Устройства и питание возвращаются автоматически, старые callbacks не управляют новым подключением | Не проверено |
| S02 | Гибернация и Fast Startup | Корректное восстановление отдельно от холодного старта | Не проверено; не приравнивать к обычной перезагрузке |
| E01 | Слабый блок, перегрузка, временный сбой PMIC | Безопасное ограничение с понятной причиной; после устранения — автоматическое восстановление | IRQ-storm путь Windows отправляет suspend; восстановление требует доразбора |
| E02 | Ошибки чтения/команд | Ошибка не превращается в успех, нулевое напряжение или фиктивное отключение | Неполный двухканальный ABI блокирует старые fix2/fix3 |
| G01 | Процент и статус батареи | Достоверные процент/наличие питания/приём тока, без ложного «заряжается» по одному VBUS | В текущем переводе PowerStatus используется детектор VBUS, не измерение тока |
| G02 | Полная батарея, температурные ограничения | Статус объясняет штатную остановку заряда; нулевой ток при 100% не объявляется поломкой | Не проверено; защиты сохраняются |
| G03 | Обычная и быстрая зарядка | Напряжение и ток соответствуют реальному согласованию PD либо QC и ограничениям устройства | Старые замеры содержат PD через хаб и HVDCP3 напрямую; нынешний Apple-блок ими не идентифицирован |

## Когда накопитель действительно не должен прерываться

P01/D01 означают отсутствие электрического перезапуска хаба/SSD и отсутствие
программного detach/reset. Автоматическое повторное появление диска через
секунду **не засчитывается** как непрерывная работа или сохранность записи.
При действительном пропадании питания драйвер не может сохранить уже
оборвавшуюся USB-сессию.

В архивной конфигурации DeviceCap2=0x0003: биты объявления Sink FRS и Source
FRS равны нулю. Это описание текущего интерфейса, не доказательство
невозможности FRS в самом железе. Установка этих битов без реализации
аппаратного переключения не решает проблему.
[TCPCI, таблица 4-29](https://www.usb.org/sites/default/files/documents/usb-port_controller_specification_rev2.0_v1.0_0.pdf).
Производитель хабов также описывает разрыв питания/отсутствие FRS как причины
отключения при снятии PD-блока; модель пользовательского хаба неизвестна,
поэтому это пример механизма, не диагноз его модели.
[Пример Anker](https://service.anker.com/eu/article-description/Why-does-the-hub-disconnect-and-reconnect-when-I-unplug-the-PD-wall-charger-A210C).

## Обязательные условия реализации до предложения установки

- [ ] K01. Полностью определён ABI между qcusbctcpm, qcpmictcc и qcpmicext: NTSTATUS и vendor-status сохраняются независимо; нет ложного успеха.
- [ ] K02. Состояние Initializing снимается только после успешной инициализации и достоверного начального снимка; уже подключённый аксессуар обнаруживается без новой физической грани подключения.
- [ ] K03. Source/OTG и Sink управляются одним согласованным путём; старый таймер не может включить источник после detach, Sink или Stop.
- [ ] K04. Sink-команды 0x44/0x55 выполняются в соответствии с объявленными возможностями; пределы PD/QC и термозащита сохраняются.
- [ ] K05. CC/Power/Fault/RX/TX доставляются последовательно, без потери новых событий и без общего lock вокруг вызова Windows.
- [ ] K06. При IRQ-storm защитная приостановка имеет владельца, причину и безопасный путь восстановления; нельзя просто принудительно обнулить suspend в работающей системе.
- [ ] K07. Stop отменяет старую работу и ждёт допустимое завершение потока/callbacks до освобождения контекста. Нет двойного завершения запроса или повторного закрытия handle.
- [ ] K08. Ошибки ресурсов/старта видимы вызывающему коду; временный сбой не оставляет порт без обработчика навсегда.
- [ ] K09. Определено взаимодействие с существующим Windows PD-движком и ACPI Capability Store; не добавлен второй конкурирующий Android PD-движок.
- [ ] K10. Сохранены boot-start зависимости и совместимый battery miniclass1680; исторически падавший miniclass2100 не возвращается.
- [ ] K11. Для будущего кандидата зафиксированы исходники/изменения, хеши, подпись, каталог и точный состав пакета, а также соответствующий ему откат. Одного разбора Ghidra недостаточно для заявления «BSOD исключён».
- [ ] K12. После будущего отдельного разрешения пройдена матрица B/C/P/D/S/E/G с записью условий, ошибок и длительности. Сейчас это не разрешение начинать тесты.

Windows уже содержит PD-движок UcmTcpciCx; портовый драйвер должен правильно
переводить команды и сообщать события. Системные сведения из ACPI также
влияют на политику.
[Документация Microsoft](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/write-a-usb-type-c-port-controller-driver).

## Как фиксировать будущий результат

Для каждой строки: точные хеши всех компонентов, тип старта/исходный режим,
модель блока/хаба/кабель/накопитель, установленный PD/QC-контракт, роли,
реальный статус питания, события перечисления USB и ошибки. Для D01 —
непрерывность I/O и проверка содержимого, а не один значок диска. Для каждого
подтверждения записываются число повторов и наблюдавшийся диапазон задержки;
пустое поле не считается успехом. Проверку проводить только после нового
разрешения владельца, отдельным согласованным этапом.

HDMI остаётся отдельным неустановленным вопросом возможностей дисплейного
тракта/Alt Mode. Само наличие HDMI на хабе и исправление зарядки не являются
подтверждением видеовыхода планшета.
