# PMIC 1849: собранный кандидат для контролируемого испытания

27.10.2026. Пакет **1.0.1849.0** собран EWDK и подписан существующим
тестовым сертификатом. Это первое узкое исправление из нового расследования,
а не завершённый драйвер зарядки/PD/USB. **Не установлен, загрузка не проверена.**

## Исправление

Основа — текущий штатный пакет1840, SHA256 исходного SYS:
`533C3A555E111D4B12B657D026C92D63D5170D57297432D03BDAF3BE96C7886A`.
Встроенная PE FileVersion1680 не равна версии INF1840: это тот же исходный SYS,
который выбран в текущем oem92.inf, а не смена базового драйвера.

В1C28 четыре операции `MUL W8,W8,W9` заменены прямыми вызовами четырёх
арифметических листовых обработчиков. Добавлено112байт RX-кода без доступа
к памяти, новых импортов, кадров стека, фоновых потоков, таймеров и IOCTL.
Исходные entry point, unwind, CFG/load config, WDF и обработка ошибок сохранены.
Изменение INF — только DriverVer. Процент батареи обрабатывают прежние
battery manager/miniclass; miniclass2100 не используется.

Windows-параметры в мА/мВ переводятся в код каждого регистра отдельно:

|Регистр|Параметр|Код|Верхняя граница|
|---|---|---|---|
|1061|FCC|мА /50|5900мА, потолок платы|
|1070|Float voltage|(мВ−3600)/10|4470мВ, потолок платы|
|1370|USB input current limit|мА /50|3000мА, потолок платы|
|118C|DC input current limit|мА /40|1200мА, предел профиля PM8150B|

Сначала ограничивается диапазон, затем выполняется целочисленное деление.
Нижняя граница FV3600мВ соответствует профилю Android; для токов —0.
Меньший запрос Windows сохраняется с округлением вниз по шагу, а не заменяется
максимумом платы. Возможности подключённого блока не выводятся из потолков
таблицы. Например, запрос USB1500мА даёт код30 вместо прежнего96.
118C — **DC ICL**, не лимит OTG. Регистр OTG1152 не меняется.

Единицы Windows установлены по вызывающему battery213A8: ограничения4500,
3487..4919,4800,3000 и отдельная обработка500/900. Публичного vendor ABI-header
нет; это вывод по бинарному коду, связанный с текущим BMNR=1.
Фактические аргументы исторического отказа не были захвачены.

## Выполненные проверки

- 266156 запусков реального ARM64-кода обработчиков в Unicorn: все0..65535
 для каждого параметра, границы и воспроизводимые32-битные случайные входы.
- 259 сценариев полного setter/dispatcher с исполнением настоящих5C78 и4AC8
 до имитированного WDF-вызова. Проверены null, отсутствие нижнего target,
 NTSTATUS, положительные transport-коды, vendor error, неправильная длина,
 WPP logging, сохранность регистров, x18, балансы lock и три других ASLR-базы.
- 1081 снимок границ инструкций проверен нативной ARM64 Windows:
 1887 шагов RtlVirtualUnwind и80 переходов из leaf без pdata, ошибок0.
 Повторено на подписанном SYS. SYS отображался как неисполняемые данные.
- Повторная сборка побайтно совпала с неподписанным SYS. После подписи все
 отображаемые секции совпадают с проверенной сборкой; RWX нет.
- InfVerif `/u` прошёл. Проверены тестовая подпись и членство INF/SYS в CAT.
- Установщик запущен только в Inspect: текущий oem92/1840, miniclass1680,
 каталог доверенный. Отсутствие прав администратора подтверждено.

Числа выше — проверки ограниченного кода и моделируемого транспорта,
**не испытания зарядки на железе и не гарантия отсутствия BSOD**.
Напряжение, реальный зарядный ток, загрузка, сон и USB hotplug не проверялись.
Подпись тестовая, не production/WHQL; обычный Secure Boot не заявлен.

## Что ещё не исправлено

Остаются рассогласование suspend-кэша между battery/Type-C, незавершённые
Sink-команды, ранняя готовность, stale Source-таймер, lifecycle/stop и Fault.
Эта сборка не меняет роли Source/Sink, протокол PD/QC, charge pump,
USB-перечисление или условия восстановления. Не обещает непрерывный I/O
при снятии питания с хаба. Сначала испытывается именно кодирование параметров;
смешивание с R1..R6 или TypeC safetyfix3 недопустимо.

## Перед будущей установкой

Сейчас кодекс запущен без административного токена. Ничего не добавлено
в DriverStore и не привязано к устройству. Снимок SYSTEM/BCD **для этой
новой попытки ещё не создан**: старые сохранённые снимки не выдаются за свежие.

Установщик по умолчанию Inspect. Stage требует повышенные права,
`-AcknowledgeExperimental`, уже включённое test signing, доверенный сертификат,
Secure Boot off, точный исходный SYS и miniclass1680. До Stage сохраняются
полный SYSTEM/BCD и текущий пакет на внутренний диск.

Activate требует успешный Stage именно этого пакета и проверенный внешний
rescue-набор, включая SYSTEM до Stage. Он может изменить живую PnP-привязку:
до него должны закончиться копирования на внешние диски. Автоперезагрузки,
удаления PMIC-устройства, смены host mode и правок BCD нет.

Старый комплект отката остаётся в
`H:\Vlad\Charging\Charging-Rollback-2026-10-26`.
Дополнительные копии текущих пяти пакетов и метаданные подготовлены
в подпапке `before-pmic1849-encoding`; это файловый резерв, не полный новый SYSTEM.
После повышения прав необходим свежий полный rescue до активации.

Для следующей сессии: открыть Codex от имени администратора, проверить
сохранённые QA/подписи и состояние, выполнить Stage, проверить внешний rescue,
затем контролируемую активацию. Первый аппаратный этап — загрузка и стабильное
питание с одной неизменной схемой подключения. Hotplug не считать исправленным
по появлению одного значка AC.
