# Выбор алгоритма зарядки подтверждён текущей конфигурацией ОС

27.10.2026. Найдено недостающее звено между прошивкой nabu и ранее
разобранными функциями battery manager. **Новой сборки, установки,
эмуляции, физических тестов и обращения к шине/регистрам PMIC не было.**
Дополнительно выполнено только чтение кэшированной ACPI-таблицы из реестра
Windows, ключей конфигурации и файлов драйверов. AML не исполнялся.

## Главный результат

В текущей сохранённой Windows таблице DSDT устройство PMBT с
_HID=QCOM0531 содержит BMNR, где первый элемент равен1. Текущего
переопределения Services\qcbattmngr\WDF\SelectPlatform нет.
В разобранном qcbattmngr этому значению соответствует набор обработчиков
с146A0/149C0 — тот путь, в котором находятся управление suspend17EE8
и передача параметров213A8.

Хеши файлов, указанных в текущих ImagePath служб, совпали с хешами
разобранных архивных SYS. Следовательно, связь с нужным платформенным
алгоритмом теперь подтверждена **конфигурационно**, а не по предположению
о названии драйвера. Фактическое значение поля контекста ядра и выполнение
ветвей в момент прежнего отказа не считывались. Это не доказательство
устранения сбоя и не заявление о безопасной загрузке нового пакета.

## 1. Старый дамп действительно существовал, но текущая таблица другая

## 2. BMNR разобран как структура AML, не только строковым поиском

В текущей DSDT Device PMBT начинается с0x69B, BMNR расположен
в0x78C..0x7BC. Проверены:

- Заголовок DSDT, объявленная длина и ACPI checksum.
- Границы Device и Method через AML PkgLength и _HID QCOM0531.
- MethodFlags с нулём аргументов.
- Name(CFG0), Package с пятью элементами и отдельное декодирование констант.
- Оставшаяся последовательность Store/Index/Return до границы метода.

Узкий декодер реконструирует:

```asl
Method (BMNR, 0, NotSerialized)
{
    Name (CFG0, Package (0x05) { One, Zero, One, Zero, "CUST_PMIC" })
    Store (CUST, Index (CFG0, 0x04))
    Return (CFG0)
}
```

Это реконструкция одного метода, не полный вывод iasl. Единственная
запись в пакет в теле метода затрагивает элемент4 — строку CUST.
Элементы0..3, в том числе селектор1, здесь не меняются. Значение
переменной CUST этим декодером не вычисляется.
Правила длин пакетов и кодирования Method/Package/констант сверены с
[официальной спецификацией AML](https://uefi.org/specs/ACPI/6.5/20_AML_Specification.html).

Декодер ничего не исполняет и прекращает работу при другом формате
или неожиданной последовательности. Для старого и текущего файлов
сохраняются отдельные результаты, чтобы не смешивать источники.

## 3. Цепочка Windows теперь связана с BMNR=1

В Ghidra повторно проверены D218 иCE48; сопоставлены уже разобранные
4148/4D08,146A0,17428,17EE8 и213A8:

```text
PMBT / QCOM0531 / BMNR[0] = 1
  -> parser4148: context+9C0
  -> возможный override4D08: Services/qcbattmngr/WDF/SelectPlatform
  -> CE48, selector==1:
       callback slot28A40 = 146A0
       callback slot28A48 = 149C0

D218 -> slot28A40 ->146A0
  ->17428 ->213A8 ->801B0FA0 ->PMIC1C28 ->регистры параметров
  ->17EE8 ->801B0FE4 ->PMIC2628 ->suspend USB/DC
```

При другом селекторе CE48 задаёт DAC0/DB10. В текущей конфигурации службы
ключ WDF отсутствует, как и Platform/ParallelCharging. Это новое чтение
кэшированных настроек ОС, отдельно от прежнего SYSTEM-before-rollback.

Вывод: **исправление рассмотренного пути соответствует текущему выбору
конфигурации**. Но успешное выполнение BMNR при старте, его дальнейший
разбор и реальный проход конкретной ошибочной ветви в момент сбоя
не наблюдались трассировкой. Эти уровни доказательства не смешиваются.

## 5. Что это меняет в приоритете исправления

Первые конкретные задачи теперь привязаны к выбранному профилю:

1. PMIC1C28: корректный перевод мА/мВ в коды1061/1070/1370/118C по
   таблице PM8150B, без умножения и усечения до байта; сохранить board,
   контрактные и температурные ограничения.
2. Согласование17EE8 иTypeC9AA0: внешняя запись suspend не должна
   оставлять достоверным кэш старого запроса. Отдельные причины запрета,
   безопасный выход из recovery и отмена устаревших операций питания.
3. Закрыть ранее найденные проблемы ABI, готовности, Source-таймера,
   Fault и завершения потока. Один исправленный коэффициент не закрывает
   ошибки USB-переключения и безопасность загрузки всего комплекта.

Это план реализации, **не новая готовая сборка**. Чек-лист32 сценария/14
условий остаётся непройденным для нового исправления. Непрерывная работа
SSD при снятии питания хаба по-прежнему зависит и от электрического перехода.

Следующий статический шаг: зафиксировать минимальный набор согласованных
изменений PMIC/Type-C/battery-owner и проверить контракты ошибок/завершения
на каждом выбранном месте до сборки кандидата. Не менять действующий
комплект и не начинать аппаратные тесты по этому отчёту.
